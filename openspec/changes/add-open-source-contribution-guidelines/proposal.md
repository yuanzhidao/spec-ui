# Add Open Source Contribution Guidelines

## Why

spec-ui is moving toward public collaboration. The project needs lightweight contribution, review, issue reporting, and licensing documents before opening the repository so contributors understand the expected workflow and maintainers can review changes consistently.

## What Changes

- Add public contribution guidance with project setup, branch/worktree expectations, OpenSpec-first workflow, coding standards, dependency policy, verification requirements, and PR expectations.
- Add a lightweight public `README.md` with project purpose, status, setup, development commands, OpenSpec workflow, desktop note, and license.
- Add GitHub issue templates for bug reports and feature requests.
- Add a pull request template that requires motivation, scope, screenshots or logs when relevant, verification commands, breaking-change disclosure, dependency disclosure, and OpenSpec status.
- Add an Apache-2.0 project license.
- Keep all public documents English-first and focused on spec-ui's own workflow.

## Non-Goals

- Do not add release automation, changelog generation, code signing, or package publishing workflows in this change.
- Do not define project governance roles beyond basic maintainer review expectations.
- Do not add a code of conduct, security policy, or dependency update automation until public contribution volume requires them.
